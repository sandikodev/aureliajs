# Aurelia App Craftsman (Fullstack & Frontend Engineering Skill)

> **Lens & Posture:** You are a **Product-Minded Fullstack Engineer & Frontend Craftsman**. Your priority is developer experience (DX), application ergonomics, clean readable business logic, and zero unnecessary boilerplate. You write application code that is a pleasure to read, test, and maintain.

---

## 🧠 Core Philosophy

1. **Write Applications, Not Framework Plumbing**:
   - If you find yourself writing repetitive `document: { cssBundle, jsBundle }`, manual `window.__HYDRATION__` unpacking in `attached()`, or manual `isLoading = true; try {} finally {}` state machines, **STOP**. Leverage the native framework capabilities (`@hono/aurelia` and `@aureliajs/vite-plugin-aux`).
2. **Co-locate Everything Relevant**:
   - Route data loaders, auth guard requirements, page titles, and UI presentation belong together in the component, not scattered across 4 different routing files.
3. **No Split-Brain Routing**:
   - Do not maintain separate CSR routers and server route handlers for the same page. The Hono route adapter handles SSR, streaming, and JSON content-negotiation simultaneously.

## 🛠️ Canonical Patterns for Application Developers

### 1. Route Definition (The Clean One-Liner)

Never duplicate document configurations or data loading in `index.ts`. Declare the route cleanly:

```typescript
// src/index.ts
import { Hono } from 'hono';
import { aurelia } from '@hono/aurelia/server';
import { PostDetailPage } from './pages/post-detail.js';
import { DashboardPage } from './pages/dashboard.js';

const app = new Hono();

// Single-line route binding:
// Loader, title, auth guard, and metadata are automatically extracted from the component!
app.get('/posts/:slug', aurelia(PostDetailPage));
app.get('/dashboard', aurelia(DashboardPage));
```

---

### 2. Modern Single-File Components (`.aux`) with `<script setup>`

Write SFCs with `<script setup lang="ts">`. You do **not** need boilerplate classes, constructors, or `<template bindable="...">`:

```html
<!-- src/components/UserProfileCard.aux -->
<template>
  <div class="user-card rounded-xl border p-4 shadow-sm bg-card">
    <div class="flex items-center gap-3">
      <img src.bind="avatarUrl" alt.bind="name" class="size-10 rounded-full" />
      <div>
        <h3 class="font-semibold text-foreground">\${name}</h3>
        <p class="text-xs text-muted-foreground">\${role}</p>
      </div>
    </div>
    
    <div class="mt-4 flex justify-between items-center">
      <span class="text-sm">Reputation: <strong>\${points}</strong></span>
      <button click.trigger="endorse()" class="px-3 py-1 bg-primary text-white rounded text-xs">
        Endorse (+1)
      </button>
    </div>
  </div>
</template>

<script setup lang="ts">
// Inferred Bindables (Props):
// Any top-level 'let' without '_' prefix is automatically registered as a bindable!
let name: string = 'Anonymous';
let role: string = 'Member';
let avatarUrl: string = '/default-avatar.svg';
let points: number = 0;

// Internal State & Methods:
let _isSubmitting = false;

function endorse() {
  if (this._isSubmitting) return;
  this.points++;
}

// Lifecycle Hooks:
function attached() {
  console.log(`Card mounted for \${this.name}`);
}
</script>

<style scoped>
.user-card {
  transition: transform 0.15s ease-in-out;
}
.user-card:hover {
  transform: translateY(-2px);
}
</style>
```

### 3. Co-located Server Loaders & Execution Boundaries

When a page requires server data, co-locate the loader and specify execution boundaries:

```html
<!-- src/pages/PostPage.aux -->
<template>
  <article class="max-w-3xl mx-auto py-8">
    <h1 class="text-3xl font-bold">\${post.title}</h1>
    <div class="mt-4 prose dark:prose-invert inner-html.bind="post.content"></div>

    <!-- Client-Only Island: 3D interactive chart not executed on server -->
    <template client-only>
      <interactive-analytics post-id.bind="post.id"></interactive-analytics>
    </template>

    <!-- Server-Only Island: Static footer with 0 client JS footprint -->
    <template server-only>
      <footer class="mt-12 text-center text-xs text-muted-foreground">
        Generated by Aurelia 2 SSR at \${timestamp}
      </footer>
    </template>
  </article>
</template>

<script setup lang="ts">
// Initial state automatically hydrated from server loader
let post = null;
let timestamp = '';
</script>

<!-- Server-Only Script: 100% stripped from client bundle (zero secret/DB leaks) -->
<script server lang="ts">
import type { Context } from 'hono';
import { db } from '@/db';

export const title = 'Article Detail';
export const requiresAuth = false;

export async function loader(c: Context) {
  const slug = c.req.param('slug');
  const post = await db.posts.findBySlug(slug);
  return {
    post,
    timestamp: new Date().toISOString()
  };
}
</script>
```

### 4. Pure Template Components (Zero-Script UI Primitives)

For simple presentational wrappers (slots, styling), omit `<script>` completely:

```html
<!-- src/ui/CardHeader.aux -->
<template containerless>
  <div class="flex flex-col gap-1.5 p-6">
    <au-slot></au-slot>
  </div>
</template>
```
*The compiler automatically generates `export class UiCardHeader {}` and registers the tag `ui-card-header`.*

---

### 5. Client Bootstrap with Auto-Hydration

In `src/client.ts`, eliminate manual unpacking:

```typescript
// src/client.ts
import { createClientHydrator } from '@hono/aurelia/client';
import * as pages from './pages/index.js';

// Pass all pages directly; the hydrator auto-detects the matching component
// from window.__AURELIA_HYDRATION__ and automatically injects loader data & context!
createClientHydrator({
  components: pages,
  target: 'app-root'
});
```

## 🚫 Anti-Patterns to Reject

| ❌ Anti-Pattern (Reject) | ✅ Clean Craftsman Pattern (Adopt) |
| :--- | :--- |
| Writing `async attached() { this.data = await fetch(...) }` on page components. | Use `static loader(c)` (or `<script server>`). Data is pre-rendered on server with **0 layout shift (CLS)**. |
| Writing `isLoading = true; try { ... } finally { this.isLoading = false; }` on page loads. | The server loader resolves data *before* rendering. The initial HTML is complete; no loading spinner flash. |
| Manually writing `hydrateFromServer()` and assigning 10 properties in `attached()`. | Trust `createClientHydrator()`. It auto-assigns `initialData` and `context` onto the root component instance. |
| Repeating `document: { cssBundle, jsBundle }` on every route in `index.ts`. | Use router-level defaults (`aureliaDefaults` or single shared config). |
| Dummy `<script lang="ts">export class Name {}</script>` in template-only `.aux`. | Omit the script tag. The compiler derives the class name from the file. |
| Secret DB queries or API tokens inside standard component classes. | Place server-only logic exclusively inside `<script server>`, guaranteeing 0 bytes leak to client. |
